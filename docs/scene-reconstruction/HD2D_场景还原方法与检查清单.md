# HD2D 场景还原方法与检查清单

目标：在 `KongGames/godot_scene` 还原指定的《三角战略》地图。先确认**棋盘、表现层和启动状态**，再恢复材质、光照与镜头；资产导入成功不等于画面还原完成。

## 1. 目录与范围

- 工程：`godot_scene/`；共享网格、纹理和 shader，逐图隔离 `data/scenes/<id>/`。
- 工具：`tools/scene_reconstruction/`；配置、原始数据、日志、截图：`reconstruction/<scene>/`。
- 还原工程的棋盘使用 `SB_*`，不是原版地图名或正式用途证明。盐湖为 `SB_C0_EX_Saltlake`，资料位于 `reconstruction/sandbox/maps/SB_C0_EX_Saltlake/`。
- 根据任务选择入口；Preview、世界地图、测试图不能自动算作待还原战场。WB 保存规则，GFX/OTH 提供画面，不把 WB 占位方块画出来。
- 资源按完整包路径和哈希识别；短名只用于显示。失败要报告，不能静默跳过。

## 2. 处理顺序与方法

| 步骤 | 必须恢复的内容 | 处理与检查 |
|---|---|---|
| 入口与状态 | 战斗入口、WB、GFX、OTH、变体 | 沿 `LevelStreaming.WorldAsset` 核对依赖；记录完整包路径。显隐继承模板，必要时追构造脚本、BeginPlay/Reset，区分完整和破坏后的替身。 |
| 组件与变换 | Blueprint/CDO/SCS、ChildActor、ISM/HISM、socket | 合并模板与实例覆盖，按完整对象身份去重。ISM/HISM 逐条展开 PerInstanceSMData，世界变换＝组件世界变换×实例局部变换；零实例不生成占位网格。当前换轴 `UE(x,y,z)cm → Godot(x,z,y)m`，避免重复根变换。 |
| 槽与顶点数据 | section、逐槽覆盖、UV、顶点色 | 空覆盖沿用默认材质；保留 section→UE 槽号，不猜 glTF 表面顺序。使用原始 LightMapCoordinateIndex；光照不得覆盖流场 UV。实例顶点色生成派生网格并核对映射误差。 |
| 材质有效输入 | MI/MID 父链、静态开关、默认纹理 | 先按 LoadedShaderMap 读取有效 uniform、默认值及 TextureIndex 引用，再叠加实例覆盖。`None` 名称可能是有效固定纹理；同名 `_1` 参数未必参与计算。检查 sRGB/线性、采样和通道。 |
| 材质计算 | 分层、渐变、透明、水、晶体、闪光 | 按编译家族实现；明显差异按 ResourceHash 对应 DXBC/preshader 追踪公式。顶点色语义逐家族确认；不能一律当颜色或透明度，也不能把所有水面套成港口水。 |
| 烘焙与环境光 | Lightmass、SkyOcclusion、静态阴影、天空与云影 | 按本关卡 BuiltData 的 GUID 和 UV scale/bias 绑定；ISM/HISM 另取对应序号的 PerInstanceLightmapData，分别覆盖光照/阴影 bias。保留亮度残差 alpha，关闭 alpha border 修复；天空辐照度与反射分开，太阳和云影读取本图参数。 |
| HDR 与镜头 | 曝光、Bloom、Film/LUT、边缘效果、景深 | HDR 中先合成 Bloom，再 Film/颜色转换和显示域效果。UE 水平 FOV 对应 KEEP_WIDTH。浏览相机围绕有效棋盘，不受外围大水面影响；景深随距离缩放，移动、旋转、缩放和重置一起验证。 |
| 动态与对照 | 时间、天气、粒子、动画、角色 | 固定时间比较材质，再看多时刻、多方向和近景。像素角色保持尺度与采样。原版和 Godot 必须同状态、同机位才能用差分衡量还原度；自动机位须标明来源。 |

排查顺序：**入口/状态 → 几何/槽/UV/顶点色 → 材质有效分支 → 光照 → 后处理**。缺光照图不靠提亮补救，错材质不靠全图调色补救。

## 3. 已验证的易错点

- **棋盘漏项或重复计数**：用战斗类→流送 WB→格子/WBAsset→战斗表核对；不能只搜 `_battle_数字`，也不能因资源名含 test 就排除。分别统计入口、WB、布局与表现状态；表未登记的完整资源单列待确认。格子缺省属性继承 CDO，`BP_BaseBlock_C.Height` 默认是 1。
- **布局始终对不上**：先查 GFX 变体与启动状态；港口曾误用另一版本，街区升降墙曾漏 BeginPlay→Reset。
- **整片白、绿、黑**：先查槽号、绑定路径大小写、实例顶点色；再查 BuiltData 的关卡、GUID 和 UV，不先改曝光。
- **旋转时地面阴影碎裂、闪跳**：先排除共面重叠。盐湖曾漏掉 ISM 实例变换，将外围水面摆在组件原点，与细分湖面争抢深度；还需接入每实例光照/阴影偏移。固定动画、关闭实时阴影仍抖，优先查几何和 UV；不要先抬高水面或调 shadow bias。
- **水面像铺了雪**：盐湖 `M_ENV_SaltLake` 是不透明的水/盐混合材质。顶点 alpha 控制盐层权重；需恢复世界坐标盐遮罩、四向波纹、Fresnel 水色、反射与闪光。
- **表面有纹理却缺 HD2D 质感**：盐岩/女神像的 SandSpec 需要独立的法线与高光纹理。其闪光加到底色并饱和；湖面闪光进入自发光，两者不能混用。
- **继承参数齐全仍不对**：有效分支可能使用父材质编译引用表中的默认纹理。检查 TextureIndex，不能只读取 MI 显式覆盖。
- **高光死白或泛光不对**：检查 HDR 顺序、线性纹理、取幂对象和实际启用参数，再调跨引擎响应。

## 4. 运行与验收

盐湖定向更新和回归，在 `KongGames/` 执行：

```powershell
python tools/scene_reconstruction/restore_saltlake.py --verify
```

该命令更新盐湖材质和实例装配，复用原始网格与关卡状态，并在真实设备回归；加 `--capture-orbit` 保存整圈旋转。阴影分项检查用 `verify_shadow_rotation.gd`，报告留在本图目录。完整导出复用 `build_scene.py`、`sandbox_scenes.py`，先核对范围，不重跑无关场景。

每张图交付前检查：

- [ ] **来源正确**：棋盘、表现层、状态和机位来源均已记录。
- [ ] **资源守恒**：源组件＝去重＋有理由排除＋生成组件；另核对 ISM/HISM 展开实例数，生成失败为零。
- [ ] **输入完整**：逐槽材质、UV、顶点色、有效默认纹理、BuiltData 无静默遗漏；未绑定项逐条说明。
- [ ] **真实运行**：日志无脚本/shader/资源错误，切换与重新加载正常，移动/旋转/缩放/重置正常。
- [ ] **视觉复核**：查看全景、近景、反向、多时刻及连续旋转；固定动画后比较同一世界点，区分正常高光、阴影边缘采样与深度争抢。
- [ ] **结论有据**：区分“已实现”“已运行验证”“已与原版对照”；未实测的运行时曝光、天气、剧情或破坏状态单列，不写成完全一致。

故障记录统一写成：`对象 → 症状 → 原始证据 → 根因 → 修复 → 回归结果`。公共方法留在本文，各图的参数、截图和限制留在本图报告。
