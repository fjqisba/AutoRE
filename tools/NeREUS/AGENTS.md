# NeREUS解混淆引擎

整个解混淆引擎就是一个状态机。

1、最开始空状态的时候，执行`init_vm_context`，参数为输入vm虚拟机函数的入口地址，先获取一块基本块，基于`remill`引擎生成合并IR，做寄存器与栈内存传播、临时操作消除类似的基本优化，在不会误删核心IR的前提下，生成最终IR。

2、通过解析IR，拿到关键的VIP指针(指向VM虚拟机字节码数据)的那一刻，后续就执行`fetch_block`，目标是分析语义控制流程。

3、分析过程中，还要逐渐通过更新的方式形成完整的VM语义流程图，在语义流程图中，(`RIP/EIP`真实指令地址，VIP虚拟地址)组合起来作为语义地址，地址给我使用十六进制啊，同一个handler基本块被进入，但是语义地址不一样，在流程图中不视为同一个节点。

4、语义流程图是包含每一条汇编指令的，应该使用dot svg来表示和阅读，禁止生成并阅读png。

## 其他细节

- 地址文本化一律使用十六进制，例如`0x181562C26`，而不是`6464875558`。
