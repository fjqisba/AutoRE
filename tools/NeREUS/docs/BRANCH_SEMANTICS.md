# vjmp 的分支语义与增量语义图

分析顺序是：先化简目标数据流并分类，再决定是否扩展合并。不能把所有间接 JMP 都视为 JCC，也不能对两条存活边任选一条做线性合并。

进入分类前必须完成 [IR / 状态驱动的不动点](LOCAL_OPTIMIZATION.md)。worker 与快照外层均稳定后才允许求解目标；资源耗尽、振荡或内层未收敛时先保存 `optimization.progress.json`，抛出 `OPTIMIZATION_NOT_CONVERGED`，不把中间表达式分类成 `computed-indirect`。不动点表示当前抽象传播稳定，不保证每条间接跳转都能解析。

## 只读映像快照传播

当前初始化状态机可对目标计算或 Context 写入依赖的映像读取提供显式快照事实。事实包含 VA、字节、输入文件 SHA-256 和首选 ImageBase；只从唯一、只读且有原始数据的区域提取，不能从缺页或可写区域填零。

优化器优先使用路径上的最新写入。快照传播会检查先前写入：可能覆盖、基址未知或存在未知副作用时拒绝传播；入口栈与映像分离是明确的附加前提。跨轮重建整个提升链时保留已经使用的快照事实，不能在下一轮丢掉导致先前解析出的跳转重新变成不同状态。

这是条件化的离线分析，不证明运行时映像一定等于磁盘文件。原始 IR 保留；相关条件同时进入 `image-facts.json` 和优化 IR 的 `nereus.image.snapshot` 元数据。不将同一快照结论自动推广到其他进程、ASLR 基址、装载后修改或自修改代码。

## 分支分类

- `direct`：目标已经是常量，或者 SMT 证明其取值集合只有一个元素。目标有效时继续合并。
- `conditional`：当前位向量模型中的目标集合恰好两个。保存两条条件边，不按单路径追加任一后继。
- `computed-indirect`：模型仍允许三个或更多目标，不能据此恢复为 JCC。
- `unresolved`：不支持的控制流形状、求解超时或 unknown。不能归类成不可达或条件分支。

目标表达式从 LLVM SSA 的整数算术、位运算、比较、扩展/截断和 select 转为 SMT-LIB 位向量模型。已有 native JCC 的两个出口也保留原条件。未支持的纯表达式采用过近似符号输入；State 与内存读取是符号输入，当前对不同读取的关联保守处理。

求解器依次寻找目标 A、排除 A 后的 B、再排除 A/B 后的第三目标。只有最后一次查询 UNSAT，才能声称有限集合完整。三次 SAT 表明当前抽象模型未被限制为双目标，**不证明真实程序必有三个可行目标**；内存与路径关联缺失可能产生额外抽象模型。

条件目前以精确的目标谓词 `(= target A)` 与 `(= target B)` 表示，并引用保存的目标 SMT DAG；不直接猜测原始源程序的 JZ/JNE 名称。`branch.target.smt2`、排除查询及 `branch.classification.json` 保存证据，便于继续归一化成更易读的业务条件。

## 双目标的处理边界

已确认双目标时，两端都创建语义节点和带条件的边；当前初始化接口返回 `VJCC_FRONTIER`，保留完整 LLVM CFG/条件，提示需要分别探索两条路径。当前版本尚未对两条分支启动独立状态队列，也未建立合流 phi 或循环不动点。因此不能把图中的 `discovered` 节点写成已完成分析。

这是逐步建立流程图的明确前沿。单目标已实现自动推进；多路径后继探索和合流是后续恢复引擎工作，不通过擅自选择分支伪装完成。

## VIP 与语义地址

VIP 不由固定寄存器名决定。引擎先记录“寄存器中保存的地址确实参与 guest 读取”的流指针候选，再关联运行时 Context 中同一槽位的游标写入。首次槽位关联使用范围约束作为候选筛选，证据标为 `current-VM-entry-dataflow-candidate`，尚不是所有 TVM 变体通用的角色证明。

图中的语义地址绑定到每条指令。未初始化 VIP 使用 `0x0` 表示；内部仍保留 initialized/resolved 标记，避免将未初始化与求解失败混为一谈。同 RIP 不同 VIP 不合并；基本块只承担视觉分组，块键取第一条指令的语义地址。进一步的解码密钥/内存版本仍需要作为状态依赖完善，不能仅靠二元键证明任意状态可以合流。

当前初始化合并可能把多个原生块保留在同一转换函数，语义图仍保留各原生入口、输入/输出 VIP、分支分类和 Context 证据。`semantic-graph.json` 按分析推进更新，`state-machine.json` 同时携带图和游标来源。

每次更新同时导出 `semantic-graph.dot` 与纯矢量 `semantic-graph.svg`，作为主要阅读形式。每个基本块逐行显示 `(RIP, VIP)  汇编指令`，地址均为十六进制，不显示 BYTES，不在表头绑定块级 VIP。末条指令高亮；全部原生指令仍是可搜索的 SVG 文本。整个流程不生成、不读取 PNG，也不将 SVG 栅格化。

逐指令 VIP 通过独立的分析插桩副本计算：在每条 Remill 原生指令语义之前记录源序号、RIP、memory token、入口栈坐标和已由数据流识别的 seed 承载寄存器。局部优化后，从每个记录点的 memory token 逆向查找游标槽的最新版本。先前尚未建立 seed 的行保持 `0x0`；某条指令更新游标时，这一行仍显示旧值，下一条记录点读取新版本。

插桩只捕获已识别的 seed 承载者，名称来自数据流证据，不固定为 R10/R11；避免记录所有无关暂存寄存器而使原本应化简的 MBA 中间值变为观察输出。插桩产物在 `rounds/*/instruction-vip-trace/`，与不带插桩的主 IR 分离；`instruction-vips.json` 保存每条指令的来源、执行前边界、initialized 和 resolved 状态。若游标被未知写入覆盖，会保留未解析状态而不伪造确定值。

## 验证边界

回归覆盖 native JCC、CMOV 编码分支、setcc/掩码算术分支、无限目标不得误判双目标、路径写入覆盖映像事实、可写映像拒绝读取，以及同 handler 不同 VIP 的节点身份。

SMT 有限目标证明针对当前抽象 SSA 与输入前提；不替代原机器执行等价、内存别名全证明、两路径副作用验证和完整函数恢复。
